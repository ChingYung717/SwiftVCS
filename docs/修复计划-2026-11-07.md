## 2. 首批：凭据、安全语义和接口边界

### SV-01 · P1 · URL 凭据落盘与存量迁移

**证据**：`Apps/VCSExplorer/VCSExplorerApp.swift` 的 `normalizedRepoURL` 仍只裁空白/末尾斜杠，`saveCurrentSettings` 写入当前 URL 和 recentRepos；`Sources/CSVNKit/TrustStore.swift` 的 `AppSettingsStore` 负责持久化。连接层拒绝带口令 URL 并不能保护之前或失败后的设置保存。

**方案**：

1. 统一 URL 持久化清洗：拒绝/剥离 password；HTTPS 等不需要 userinfo 的协议去除 userinfo；`svn+ssh://user@host` 的 SSH 用户名是合法连接语义，须与口令区分处理，不可无条件剥离全部协议的 user 字段导致连接目标改变。持久化清洗与认证输入校验分别处理。
2. 解析失败但可能含凭据的输入不落盘，不用正则截断掩盖 URL 解析错误。最近列表、复制、日志及错误提示使用脱敏版本，不把嵌入密码自动搬入钥匙串。
3. 加载旧设置时清理 `repoURL` 和全部 `recentRepos`，去重并真正重写磁盘；仅清理内存副本不算完成。验证设置文件首次创建与已有文件替换均成功，错误可见，保留目录 0700/文件 0600。
4. 说明应用只能清理当前配置，无法自动保证已有备份里的历史明文消失；对曾保存真实口令的使用者给出更换建议，不导出带秘密的迁移备份。

**验收**：使用虚构秘密，覆盖连接拒绝/失败、打开副本、刷新、移除关联、重启、旧 recentRepos、百分号编码、IPv6 和 svn+ssh 用户名。对实际生成的 JSON 和显示内容检查无虚构口令，断言失败不打印原密码。

### SV-02 · P1 · TLS 主机名承诺与信任模式明确化

**当前事实**：`csvn.c` 的 `scoped_server_trust` 仅在上游校验失败时比较已保存叶证书，且允许 `UNKNOWNCA | CNMISMATCH`。因此当前机制是证书信任例外，不是对所有 CA 有效连接实施严格 pinning；主机名声明与掩码确有冲突。

**建议首批选择**：保留现有“核验过的证书可作为自签名/不受信任 CA 的例外”产品语义，明确文档与 UI 不承诺严格 pinning。移除对 CNMISMATCH 的接受，保持主机名、尚未生效和过期检查；提示现有主机名错误证书需要重新签发，而不是静默放行。旧证书导入数据可保留，但不再豁免主机名错误。

**验收矩阵**：在同一端点分别部署正确/替换证书，验证正常 CA、指定私有 CA、自签名匹配例外、自签名错证书、错误主机名、过期、尚未生效、其他端点及 realm 隔离。以实际 SVN 连接及认证请求结果为准，不能只看独立证书抓取成功。CA 有效但与例外证书不同，在该模式下允许，测试和文档须明确这一点。测试兼顾 `--ca`/`--trust-bundle` 两个入口。

### SV-03 · P2 · 严格 pinning 的可选实施门槛

若后续确需严格 pinning，再单独引入显式信任模式。不能只改回调条件，也不能靠另一条预探测连接保证正式连接安全。

“禁用 CA 使实际连接进入例外回调”只作为候选：必须同时控制有效主机配置中的 `ssl-trust-default-ca`、显式 `ssl-authority-files`、全局/分组继承及程序自动注入的 `/etc/ssl/cert.pem`，避免污染其他端点；验证重定向、并发和新上下文均无法借其他信任路径绕过。也可评估能直接约束实际连接的其他后端集成方式。

通过矩阵后才能宣布方案成立：受默认 CA 信任但错 pin 必拒；私有 CA 有效但错 pin 必拒；匹配证书且主机名/有效期正确才通过；无 pin 的常规 CA 模式不回归。记录 libsvn、serf、TLS 库版本。pin 与 CA 是否能组合属于模式定义，不能用空分支示例声称已解决。

### SV-04 · P1 · C 缓冲区契约

为 `csvn_connect` 增加 `out_uuid != NULL && out_uuid_len > 0` 守卫，并在网络调用前拒绝非法参数。审查 `csvn_copy_str`：先处理 NULL 目标、零容量，再处理 NULL 源，确保正容量时 NUL 结尾；调用者仍负责提供真实可写容量。

验收 NULL、负/零长度、容量 1、正常和截断输出；断言非法输入不发起网络访问。用最小 C 调用夹具和 ASAN/UBSAN 覆盖接口，合法 Swift 固定缓冲区调用保持兼容。此项是公开 C 接口缺陷，不宣称当前 GUI 可远程触发。

## 3. 第二批：所有差异入口的资源控制

### SV-05 · P1 · 有界 diff 输出与取消

涉及 `csvn_diff_capped`、`csvn_diff_revision`、`csvn_diff_urls`、`csvn_diff_sections` 及 `SVNClient.swift` 的工作副本和日志比较调用链。

1. 将仍写完整临时文件的三个入口改为有界流式接收，或复用共享的安全输出组件，明确截断/失败状态。若保留临时文件，创建位置遵守系统临时目录、保持 0600，并覆盖错误和取消清理。
2. 保留新实现“前一文件超限后，后一小文件仍能展示”和同路径多个 section 共享上限的语义，不用首个超限就一律中断的方案破坏已修复能力。
3. 当前 per-path 上限不等于总量有界：另设总文本/分配预算、section 数与 index 行缓冲上限，检查加法和容量扩展溢出。避免大量文件各占一个 32MiB 配额；总量用尽时明确返回部分结果及原因。
4. 区分“保留输出有界”与“libsvn 生成差异的 CPU/内部资源有界”。丢弃后续输出仍可能继续计算，须接入取消检查，必要时设置生成预算；内部大文件行为通过采样确认，不承诺常数内存。
5. 建立调用级预算并跨 Swift 的多个 diff group 累计，避免每组重置总量限制。保留复制/替换目录、多 section、过滤路径和二进制识别结果。

**验收**：单个超大文件、许多中等文件、超限后小文件、同路径重复 section、父子目标顺序互换、复制/替换目录、历史 URL 对比、取消、磁盘不可写。记录输出字节数、峰值临时文件大小、进程内存和耗时；ASAN 无错误。208MB 旧峰值仅作旧记录，完成时重新测量实际调用路径。
