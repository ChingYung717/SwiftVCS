# VCS Explorer 界面集成

本次变更涉及 SwiftUI 与本地 SVN 后端。界面通过 `AppModel` 访问 libsvn。

| 界面操作 | 调用与参数 | 结果与错误 |
|---|---|---|
| 修改连接地址或用户名 | 写入 `repoURLString` 或 `username` | 清除密码输入。更换地址也会清除待确认的证书。 |
| 连接仓库 | `connect(dismissSheetOnSuccess:)` 使用 URL、用户名、密码和「记住 HTTPS 凭据」状态 | 成功后返回仓库信息并加载目录和历史。连接期间修改地址或凭据时提示重新连接。钥匙串访问失败会显示系统错误。 |
| 抓取 HTTPS 证书 | `probeServerCertificate()` 从当前 URL 取得主机和端口 | 展示叶证书主体和 SHA-256 指纹。抓取期间切换地址时丢弃旧结果。 |
| 确认证书 | 独立核对指纹后调用 `confirmPendingCertificateAndConnect(dismissOnSuccess:)` | 验证证书属于当前端点后保存并重试连接。TLS 仍检查证书有效期和主机名。 |
| 提交改动 | `commitCheckedChanges()` 传入勾选路径和提交说明 | 有新修订时显示修订号。空提交显示没有可提交的改动。 |

升级后需要重新输入 HTTPS 凭据，并为原来使用自签名证书的端点重新核验叶证书。

## P0 工作副本操作

GUI 和 CLI 通过 `RepositoryClient` 调用 libsvn。文件操作、解决冲突和应用合并均先修改本地工作副本。用户在 Changes 中审核后提交。

| 操作 | 参数和调用顺序 | 状态与错误 |
|---|---|---|
| 删除 | 「更改」开启「含正常项」，在文件菜单选择「标记删除…」并确认。CLI 使用 `delete <工作副本> <相对路径> [路径...]` | 本地文件移除，状态为待提交删除。已有本地改动、符号链接、目录和无效路径会拒绝。 |
| 重命名 / 移动 / 复制 | 选择同目录新文件名或工作副本相对目标。CLI 使用 `rename`、`move`、`copy`，依次传工作副本、源路径、目标 | 目标已存在、未纳管父目录和越界路径会拒绝。移动两端关联，勾选或放弃时展示并成对处理。移动目标含本地改动时，拒绝放弃操作以保护文件内容。大小写不敏感卷上的仅大小写改名会拒绝。 |
| 处理冲突 | 更新或合并后到 Changes，选中文本冲突文件。先手工编辑再选「采用工作文件当前内容」，或确认采用基线、传入或冲突前本地内容。CLI 使用 `resolve <工作副本> <路径> --strategy current\|base\|incoming\|local` | 仅显示 libsvn 允许的文本策略。树、属性、二进制及混合冲突保留现场并显示类型。未解决的冲突不能提交。 |
| 合并 | 从工作副本菜单填写同仓库源 URL、修订 `N` 或 `A:B`、可选 peg。先预演，确认后应用。CLI 传 `merge <工作副本> --source <URL>`，再传 `--revision N` 或 `--from A --to B`，可加 `--peg N` 和 `--dry-run` | `A:B` 包含 `A` 之后到 `B` 的修订。干净、单一修订且完整的工作副本才可合并。预演展示预计变更，应用后展示实际状态。执行中止后刷新并检查现有变更。CLI 返回 0 表示无冲突，2 表示实际或预计有冲突，1 表示执行错误。 |
| 回滚 | 「更改」调用 `revertSelection(workingCopy:paths:)`，只回滚选中的节点与必要的移动配对路径。CLI 通过 `revert --exact <工作副本> <路径...>` 使用同一入口；省略 `--exact` 使用递归回滚。 | 递归范围含文件 external 时，整批在写入前失败，并显示阻塞路径。精确回滚目录属性不检查其子项。失败后界面刷新当前工作副本状态并显示原错误。 |
| 纳入版本控制 | 调用 `add(workingCopy:paths:)`，传入工作副本及路径数组。可直接选择未纳管目录中的现有文件；SVN 会同时纳管必要的父目录。 | 每个目标通过路径检查后才开始纳管。成功后刷新待提交列表，失败后刷新当前状态并显示错误。SDK 参数和返回结构无需调整。 |
| 精确提交 | 勾选已审核的文件与属性项。未纳管目录先用「纳入版本控制」展开文件，再逐项审核。CLI 可用 `commit --exact <工作副本> <路径...> -m <说明>` | 目录只提交自身，子项需显式列出。合并产生的待提交路径须与 `svn:mergeinfo` 一并审核和提交。 |

操作完成但刷新失败时，界面会提示重新读取状态。已有快捷键继续适用。

「更改」列表会显示本地工作副本已记录的 SVN 锁持有者。正常文件可开启「含正常项」查看。列表沿用本地状态读取。

## 节点属性、忽略规则与建目录

| 界面操作 | 参数和调用顺序 | 结果与界面处理 |
|---|---|---|
| 查看节点属性 | 在「更改」对版本化文件或目录点右键；查看正常项前先开启「含正常项」。工作副本菜单可查看根目录。在「浏览」对仓库文件或目录点右键。先确定 `PropertyTarget.workingCopy(root:path:)` 或 `.repository(URL)`，再调用 `properties(at:revision:peg:inherited:)` | 默认分别读取工作副本当前值和仓库 HEAD。行标识含目标、来源和名称；区分直接声明和继承声明，二进制值显示字节数。仓库和继承行只读。历史修订和 peg 由 SDK、CLI 提供。 |
| 设置或删除 | 在本地面板输入名称与文本，或从属性行编辑；删除需要确认。调用 `setProperty(_:value:workingCopy:path:)`，UTF-8 文本转为 `Data`，空文本转为空数据，删除传 `nil` | 保存后刷新工作副本状态和属性列表，显示待提交。二进制值用 CLI 编辑；未纳管路径、越界、只读属性和不符合 SVN 类型规则的值会报错。写入成功但刷新失败时保留成功提示并显示刷新错误。 |
| 查看忽略规则 | 本地目录属性面板调用 `ignoreRules(workingCopy:directory:)`；可直接编辑当前目录的 `svn:ignore` | 分开显示配置默认模式、目录直接声明的 `svn:ignore` 和各来源的 `svn:global-ignores`。父目录的 `svn:ignore` 不应用到后代目录。 |
| 新建目录 | 工作副本菜单选择「新建目录…」。输入相对路径，按需开启父目录选项；先调用 `previewDirectory(workingCopy:path:parents:)`，核对待建路径后调用 `makeDirectory(workingCopy:path:parents:expectedCount:)` | 路径或父目录选项变化时须匹配预览；执行时重新检查路径。目标已存在、父目录未纳管、越界、符号链接和嵌套工作副本会拒绝。操作后刷新状态；失败后也检查工作副本状态。 |

现有连接、凭据及提交入口无需适配。CLI 的本地属性路径用 `--path`，缺省为工作副本根；仓库查询传完整 URL。 `propget --raw` 的 stdout 仅含原始字节，未设置时报错；`propset --file` 可读入原始字节。

## 属性差异集成

沿用 `RepositoryClient.diff(workingCopy:paths:)` 和 `diffFile(revision:change:repoRootURL:maxBytes:)`。返回的 `FileDiff.propertyChanges` 默认为空数组，每项包含 `name`、`oldValue` 和 `newValue`，两个值均为 `Data?`。空数据是已设置的空值，`nil` 表示该侧不存在。

工作副本写入属性后，先刷新状态，再重新读取当前差异。二进制文件和目录也需检查 `propertyChanges` 后决定是否显示占位视图。文本及属性均为空时才展示无差异。遇到属性读取失败时沿用差异加载失败或错误提示。原 BASE 被替换覆盖时，后端通过原节点的仓库修订获取其属性。
